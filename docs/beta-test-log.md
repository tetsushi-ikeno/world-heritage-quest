### 不具合: 発見後の `?` と施設表示

#### r4まで

施設側で全国マップの座標を再計算していたため、`?` と施設が大きくずれて表示された。リビジョン表示を追加して `BETA r4 / PATCH r4` が確認できたことで、キャッシュではなく実装方式の問題と確定した。

#### r5

全国マップの Canvas が実際に `fillText('?')` へ渡した画面座標を取得し、施設を実座標へスナップする方式へ変更。

**実機結果**

- `?` と施設の位置ずれは改善した
- ただし、富岡製糸場を発見後に未発見の佐渡島の金山へ移動すると、佐渡の位置に「富岡製糸場と絹産業遺産群」の施設ラベルが表示された

**原因**

r5は `?` の実座標は取得できていたが、画面上の複数の `?` と27遺産のIDの対応付けを座標パターンから推測していた。画面内に候補が少ない場合、別の遺産IDを同じ `?` に割り当てる可能性があった。

#### r6

表示側も遺産ID基準へ統一。

- 発見状態は従来どおり遺産IDで管理
- 現在接触中の遺産名、センター退出時の `returnLockSiteId`、現在座標が遺産中心と一致する場合を「IDが確定できるアンカー」として利用
- IDが確定した遺産と実際の Canvas `?` 座標から画面座標の補正値を一度確定し、その補正を移動中も維持
- 発見済みIDごとに、そのIDの予測位置に一致する実 `?` だけを施設へ置換
- 未発見IDには施設を描画しない
- IDを安全に特定できない状態では、誤った施設名を表示せず元の `?` を残す

**実機結果**

- `?` は正しい遺産施設に関連付けられるようになった
- 富岡製糸場、佐渡島の金山などを移動しても別遺産のラベルへ誤置換される問題は解消

**状態**: r6 主要不具合は解消

### r8: セーブ／再開の復元不具合

**実機結果（r7）**

- センター内の本棚 `✓` は再読み込み後も保存されていた
- 全国マップの現在地は直前位置に戻らず、初期位置へ戻った
- 発見済み遺産も再読み込み直後は施設ではなく `?` のまま表示された

**原因**

- 現在地は `map.position` に保存していたが、再開時には保存座標を直接使わず、北海道スタートから移動履歴 `map.path` を再演する方式だった
- 発見済みIDは `localStorage` に残っているが、施設表示は Canvas 上の `?` を再認識・補正する仕組みに依存していたため、再読み込み直後に施設へ復元できない場合があった

**r8対応**

- ベータ用全国マップローダーに `WHQMapAPI.setPosition(x,y)` を追加
- 再開時は `map.position` の保存座標へ直接復帰する
- 移動履歴再演は通常の復元経路から外す
- 発見済み施設は `discovered` の遺産IDから外側の施設レイヤーへ直接描画する
- 施設座標は全国マップと同じ式へ補正し、施設中央を元の `?` の中心へ合わせる
- r6/r7で使用していた Canvas `?` 再認識・キャリブレーション方式は廃止
- ピラミトンの確定済み修正、九州2遺産の座標補正は維持
- 確定済み `japan-6x-map-lab.html` 本体は変更しない

**実機結果（r8）**

- センター内の腕試し等の体験履歴は保存されていた
- 佐渡付近で終了しても、再開すると知床付近へ戻ることがあった
- 施設表示が再び `?` とずれて描画される問題が再発した

### r9: 保存復元と施設描画を全国マップ側へ統合

**対応**

- 現在地の読み書きを全国マップ本体の `WHQMapAPI.getPosition / setPosition` に一本化
- ページ離脱・タブ非表示時にも現在地を保存
- 発見済み施設を別HTMLレイヤーへ重ねる方式を停止
- 全国マップの `?` と同じ Canvas 描画ループ内で、発見済みなら施設＋ラベルを直接描画
- これにより `?` と施設で同じ座標を共有し、画面サイズやカメラ位置によるズレを構造的に排除
- ピラミトン修正、九州2遺産の座標補正は維持

**実機結果**

- 発見済み施設は `?` とずれず、正しい地点に表示されることを確認

**状態**: 施設位置ずれはr9で解消。現在地の再読み込み復元は最終確認待ち。
